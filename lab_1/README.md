# Зворотне поширення похибки

Мережа: X → Linear(4, 8) → ReLU → Linear(8, 3), втрата — крос-ентропія (середнє по об'єктах), float64.

Запуск (один запуск виводить і правильну реалізацію, і дослід):

```bash
uv venv --python 3.12
uv pip install -r requirements.txt
uv run python lab1.py
```

## 1. Формули

N = 105, X (N×4), y — класи, Y (N×3) — one-hot.

Прямий прохід:

```
Z1 = X·W1 + b1        (N, 8)
A1 = ReLU(Z1)         (N, 8)
Z2 = A1·W2 + b2       (N, 3)
```

Втрата: `s = Z2 − max(Z2)` по рядку, `log p = s − log Σ exp(s)`, `L = −mean(log p[i, y_i])`.
Зсув на максимум не змінює результат, але запобігає переповненню `exp`.

Зворотний прохід:

```
dZ2 = (softmax(Z2) − Y) / N     (N, 3)
dW2 = A1ᵀ · dZ2                 (8, 3)
db2 = sum(dZ2, axis=0)          (3,)
dA1 = dZ2 · W2ᵀ                 (N, 8)
dZ1 = dA1 ⊙ (Z1 > 0)            (N, 8)
dW1 = Xᵀ · dZ1                  (4, 8)
db1 = sum(dZ1, axis=0)          (8,)
```

`softmax − Y` випливає з похідної `L = −z_y + log Σ exp(z_j)` за `z_k`; `1/N` — через усереднення.

Збережені значення з прямого проходу: `X` (для dW1), `Z1` (маска ReLU), `A1` (для dW2), `Z2` (для softmax).

## 4. Дослід із помилкою

У `backward(buggy=True)` прибрано ділення на N у `dZ2`. Дослід виконується в `lab1.py` одразу після правильної реалізації; за замовчуванням `backward` працює правильно.

Прогноз:
1. Втрата не зміниться, бо помилка лише в backward.
2. Усі ненульові градієнти збільшаться в N = 105 разів, бо `dZ2` входить у всі чотири градієнти лінійно.
3. Звірка втрати з PyTorch пройде, звірка градієнтів — ні. Чисельна перевірка теж не пройде, бо рахується через саму `loss`.

## Висновки

- Ручний backprop збігається з PyTorch до ~1e-16 і з чисельною похідною до ~1e-10.
- Помилку в масштабі градієнта не видно по втраті, її виявляють звірка градієнтів і чисельна перевірка.
